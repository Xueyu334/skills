# Enterprise Naming

定位：**按业务语义、编程语言、标识符类型提供统一词根、贴合仓库、消除中式英语的跨层命名建议**，不绑定具体开发框架。

## 1) 优先级与核心原则

1. **规则优先级**：`用户当次明确指定` > `项目明确约定及业务词典` > `项目已有的稳定命名习惯` > `Skill 行业词库与语言规范` > `通用企业英文惯例`。
   - **历史错误不无条件继承**：既有代码不一定正确；若既有代码中存在明显拼音、中式英语、语义错误（如用模糊 `*_num` 混淆编号与数量）或保留字冲突等历史遗留坏命名，**不得无条件沿用**。新增表、模块或字段优先采用规范命名；仅在必须兼容既有外部契约或原表结构时局部沿用，并显式标注遗留风险。
2. **全栈词根一致**：同一业务概念确定唯一标准英文词根后，DB 表/字段、后端类/属性、前端类型/变量、REST 路径、枚举、i18n Key 保持词根一致，**允许符合语义的词性派生形式**（如 `approve` / `approval` / `approved` 属于同一业务词根族，不应判为命名漂移）；禁止同一概念跨词根混用（如库里叫 `station`、后端叫 `site`、前端叫 `substation`）。
3. **默认语言与动态适配**：无项目上下文时，默认按 `Java + TypeScript + MySQL / PostgreSQL / Oracle / 达梦` 输出；若检测到或指定了 C#、Go、Python 等编程语言，立即按 `references/language-adaptation.md` 切换该语言的命名规则，不被 Java 习惯污染。
4. **兼容性红线**：审查或重构既有代码时，若改名涉及**数据库现有表/列、对外 REST/JSON 契约、消息队列体、或金蝶原生 BOS/EAS 元数据字段**，必须显式标注兼容性与迁移影响，不得静默改名。

## 2) 执行模式分流（优先判定）

收到请求后**先判定执行模式**，再决定是否检索仓库或读取参考文档，避免简单命名任务产生冗余工具调用与上下文开销：

| 模式 | 触发条件 | 执行方式 |
| :--- | :--- | :--- |
| **Quick** | 单词、短语、单个字段/变量/类名询问或简单中英文翻译（未要求对齐仓库、非批量设计/审查） | **轻量直出**：不检索仓库、不走完整 5 步流程；**简单命名直接作答，指定了目标就只输出该目标**（未指定具体目标或要求跨层时输出精简对照表）；遇到会影响答案的语言（如 C#/Go/Python）或领域约定（如金蝶云星空/EAS 术语）时，按需查对应参考后直出。 |
| **Contextual** | 与当前项目/具体模块相关的业务命名、新增字段/接口/类，或明确要求参考仓库风格 | **靶向检索 + 按需查规范**：最小化读取同类表/实体/类型/词典（区分稳定习惯与历史错误命名），按需加载 1~2 份相关 `references/`，输出贴合项目的跨层映射。 |
| **Audit** | 批量需求字段/建表设计、完整 DDL/实体生成、既有代码/DDL 命名审查与重构 | **完整流程**：执行完整 5 步流程与 6 项红线自检，按需查阅对应 `references/`，输出统一对照表、问题清单与兼容性风险提示。 |

**Quick 模式直出示例**（输入：`给出审批完成时间的英文标签、Java 属性和数据库列名`）：

| 类型 | 推荐命名 |
| :--- | :--- |
| 英文 | Approval Completion Time |
| Java / TS | `approvalCompletedAt` |
| 数据库 | `approval_completed_at` |

> **指定了目标就只输出该目标**：例如输入“把‘审批完成时间’翻成页面标签”，直接返回 `Approval Completion Time`，不附带整套跨层映射；若指定了其他语言（如 C#），则按对应语言惯例直出（如 `ApprovalCompletedAt`）。

## 3) 适用场景与执行流程

适用场景：**A. 单词/短语命名**（默认 `Quick`；带项目上下文时 `Contextual`）｜**B. 批量字段/表结构/实体设计**（`Audit`）｜**C. 中英文业务翻译与 i18n**（单词 `Quick` / 批量 `Contextual` 或 `Audit`）｜**D. 既有代码/DDL 命名审查**（`Audit`）。

`Quick` 模式跳过第 2~5 步直接输出；`Contextual` 仅执行最小化第 2~4 步；`Audit` 完整执行以下 5 步：

1. **识别模式与目标层**：判定 `Quick` / `Contextual` / `Audit`，确认输出范围（单语言层 vs 全栈联动）。
2. **探测仓库上下文（有项目目录且非 Quick）**：做最小靶向检索，区分**项目明确约定/业务词典、稳定命名习惯**与**历史遗留错误命名**（发现明显坏命名时不盲目沿用），确认 5 件事：
   - 编程语言与目标数据库（Java / C# / TS / Go / Python；MySQL / PostgreSQL / Oracle / 达梦；涉及字段映射或 JSON 序列化契约时再核对具体工具配置）。
   - 表前缀与单复数习惯（如 `sys_`、`biz_`、无前缀；单数 vs 复数表名）。
   - 通用字段风格（`create_time` vs `created_at`、`is_deleted` vs `deleted`、`create_by` 类型）。
   - 后端分层后缀（`Entity`/`DO`/`PO`、`DTO`/`Req`/`Cmd`、`VO`/`Resp`）与类型定义习惯。
   - 是否属于 ERP / 金蝶云星空 / 金蝶 EAS 业务语境。
3. **拆解语义并锁定词根**：按 `[业务域/限定词] + [核心主体] + [属性/动作/度量单位]` 拆解中文；优先查 `references/glossary-common.md` 或行业词库 `references/domains/kingdee-erp.md`；易混后缀与动词查 `references/semantics-and-verbs.md`。
4. **按编程语言与标识符类型映射名称**：
   - 默认参考（Java / TypeScript / DB / REST / Enum / i18n）遵循 `references/layer-conventions.md`。
   - 非 Java/TS 语言（尤其是 C#、Python、Go、SQL 过程对象）必须按 `references/language-adaptation.md` 切换规则。
5. **执行六项红线自检**（细节见 `references/abbreviations-and-guards.md`）：
   - 零拼音（国标/历史契约除外）；
   - 零中式直译（按语义区分 `count`、`quantity`/`qty`、`number`/`no`，不全局禁止 `*_num`，但避免编号与数量混用；禁用 `open_bill` 等中式直译）；
   - 使用白名单缩写、项目已有稳定缩写或行业标准缩写，拒绝无约定、高歧义的自造缩写；
   - 避开当前目标库保留字；仅当目标库存在真实语法冲突时判为兼容性风险，否则仅作跨库可移植性建议；
   - 跨层布尔命名与契约核对（分别确认字段名、访问器名、对外 JSON 键和数据库列名；Java POJO 默认避免 `is` 前缀，C# 推荐 `Is*`）；
   - 评估标识符长度（根据目标数据库版本、`COMPATIBLE` 等实例参数及字节/字符限制判断）。

## 4) 默认输出格式

直接输出可落地结果，不输出冗长规则说教：

- **Quick 模式（单词 / 短语 / 简单翻译）**：
  - **指定了目标就只输出该目标**（例如仅要页面标签或仅要字段名时直接给结果，不附带整套跨层映射）；未指定具体目标或要求跨层时，输出精简对照表：`类型 | 推荐命名`（英文 / Java·TS / 数据库，或按用户指定语言输出）。
  - 仅在用户追问或存在明显歧义时补充 1 句说明或 1 个备选。
- **Contextual 模式（项目相关业务命名）**：
  - **首选推荐**（必要时附 1~2 个备选）+ **相关层映射表**（DB / 后端 / 前端 / API / Enum / i18n）+ **1 句对齐依据**（如有沿用或规避历史坏命名则写明）。
- **Audit 模式 — 批量表/字段设计**：
  - 统一表格：`中文名 | 数据库字段 | 建议类型/长度 | 后端属性 | 前端字段 | 备注`
  - 若用户需要代码骨架，再附 DDL / Entity / TS Interface
- **Audit / Contextual — 业务翻译与 i18n**：
  - 统一表格：`中文原文 | UI 英文文案 | 枚举/常量 | i18n Key | 语境说明`
- **Audit 模式 — 命名审查**：
  - 问题列表（按严重度：`目标库保留字/兼容性风险` > `语义错误/词根漂移` > `跨库可移植性建议/风格不一致`）
  - 修改对照表：`当前命名 | 问题类型 | 建议修改 | 兼容性影响`
